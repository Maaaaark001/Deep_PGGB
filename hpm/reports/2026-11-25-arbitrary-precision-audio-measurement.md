# 任意精度音频测量：地板从哪来、窗该怎么做、哪里还有新东西

> 2026-11-25 · 分支 C 研究笔记 01 · 论文与工具箱均未改动
> 实验代码：`hpm/experiments/floor_law.py`；前置报告：`hpm/reports/float128/`

---

## 0 摘要

三件事：

1. **测量的地板不是一根线，是五级级联**：激励定义 / 输入表示 / 引擎（算术 + 算法窗）/ 输出表示 / 分析器。
   一条链的读数由**最低的那一级**决定。用这条模型预测四条实测链，误差 ≤ 0 dB（f128 链）与 −21 dB（f64 链，
   差的是引擎自己的算术）。
2. **经典"频谱泄漏"是估计器的假象，不是物理限制。** 同一段非相干数据（1000.5 Hz、4096 点）：
   单 bin 闭式投影恒在 **71.9 dB**，精度从 20 dps 加到 120 dps 一动不动；换成解完整的 2×2 正规方程，
   地板变成 **6.02 dB/bit**（实测 363 → 2362 dB），而且**与相干采样无关**。
   推论：IEEE 1241 的"相干采样"要求是闭式单 bin 估计的产物，不是测量的必要条件。
3. **可以给出证书。** 区间（球）算术把残差能量括在严格区间里，得到"零差 ≥ 1165.3 dB"这样的可证明下界。
   这对"测量"这个词是实质性的：报告的不再是一个估计值，而是一条定理。

配套结论：**计算时间不是问题**（N=4096、120 dps 的纯 Python 原型 1.3 s；C++/Arb 还会快两个数量级）；
**窗不该再用来压地板**（把窗放进模型，它对地板是中性的：1164.7 对 1164.2 dB）。

## 1 问题的形状：五级地板级联

做一次"零差"测量，误差从五个地方进来，任何一级低于目标，读数就被它钉住：

| 级 | 具体是什么 | double 链 | binary128 链 | 怎么测出来的 |
|---|---|---|---:|---:|---|
| 1 激励 | 测试信号的定义 | 整数相位，精确 | 整数相位，精确 | `(f·n) mod fs` 用整数算 |
| 2 输入表示 | 送进 DUT 的样本格式 | f64 → **328 dB** | f128 → **680 dB** | 理想音舍入后再测零差 |
| 3 引擎 | 算术误差 + 算法窗 | 算术 < 328，窗 **440 dB** | 算术 ≈ 680，窗 **440 dB** | 引擎零差随频率/窗形变化 |
| 4 输出表示 | DUT 吐出的样本格式 | f64 → 328 dB | f128 → 680 dB | 同 2 |
| 5 分析器 | 估计器 + 工作精度 | **6.02 dB/bit** | quad 分析 → 686 dB | `floor_law.py` |

**读数 = 这五级的最小值，再减去估计器的余量。** 用它检验已有数据：

| 链 | 预测（min） | 实测零差 | 差 | 差在哪 |
|---|---:|---:|---:|---|
| double 引擎 + double 分析 | 328 | 307.2 | −21 | 引擎自己的舍入再吃掉 3.5 bit |
| 80 位引擎 + 四精度分析 | 395 | 372.9 | −22 | 同上 |
| binary128 引擎 + 四精度分析 | 440（窗） | **440.2** | 0 | 已到算法窗的地板 |
| 四精度尺子自检 | 680 | 686.4 | +6 | 正确：尺子略高于表示极限 |

这张表解释了分支 C 第一份报告（float128）里所有"为什么只能到 440"的问题：不是算术到头了，
是**算法窗**成了新的最小值；C6 窗立刻把 17999 Hz 从 310 抬到 352.6 dB，就是这一级在动。

> 方法论：**在动手测之前，先写出这条链的五级数值，再问"我要测的东西在哪一级"。**
> 低于最低一级的读数一定是假的；高于最低一级的读数一定还有东西没算进去。

## 2 同类研究：有谁做过"高精度/任意精度音频测量"

结论先说：**以"任意精度"为核心、把测量地板本身当研究对象的音频测量工作，没有检索到。**
最接近的三个方向各自解决了一半问题：

### 2.1 行业与标准：做到 −120 dB 就封顶

- **Audio Precision APx555**（2014 年发布时的旗舰）：残余 THD+N 典型值 **−120 dB**。
  这是"模拟分析仪"这条路的极限，受限于 ADC/DAC 与模拟前端，不是算法。
- **IEEE Std 1241-2010**（ADC 测试标准）：频域 SINAD 的标准做法是**相干采样**，或退而求其次加窗。
  它假设分析在 float64 里做，因此整套口径的天花板就在 −300 dB 量级。
- **ADI 应用笔记 "Coherent Sampling vs. Window Sampling"**：把两条路线的取舍讲得很清楚
  （相干采样要求频率与采样率成有理比；窗采样放宽这个要求，但引入泄漏与扇贝损失）。
- **Peng et al., Sensors 2022, "High-Precision ADC Spectrum Testing under Non-Coherent Sampling
  Conditions"**：这篇最接近。它承认"实现相干采样是高精度 ADC 频谱测试的主要瓶颈之一"，
  然后用窗 + 补偿/插值在非相干条件下恢复指标。**它仍然停留在"窗是一个必须对付的误差源"，
  没有走到"把窗放进模型、用任意精度消掉这一项"。**

### 2.2 窗函数：Harris 1978 与 Slepian 1978 已经把"窗"讲完了

- **Harris, "On the use of windows for harmonic analysis with the DFT" (Proc. IEEE, 1978)**：
  窗的旁瓣、主瓣、扇贝损失的经典对照表；一万两千次引用。它讨论的是**周期图**的泄漏。
- **Slepian, "Prolate spheroidal wave functions … V: the discrete case" (BSTJ, 1978)**：DPSS，
  给定带宽下能量集中最优的窗；CCRMA 有可直接用的入门材料。
- 这两条线共同的隐含前提：**用窗去压泄漏**。本文第 3 节说，这个前提在任意精度下可以整体绕开。

### 2.3 精度：工具都齐了，只是没人拿它做音频测量

- **FFTW 官方精度基准**：给出各 FFT 实现的误差随 N 的标度，是"分析器地板"最直接的参考。
- **double-double / quad-double**（Bailey、Hida–Li–Bailey）：用两个 double 拼出 ~106 位，
  比 libquadmath 的软件模拟快得多；VkFFT 2023 年已支持 double-double 的 GPU FFT。
- **MPFR**（正确舍入的多精度浮点）与 **Arb**（Johansson 2017，midpoint–radius 球算术）：
  后者自带误差追踪，是"带证书测量"最合适的底座。
- **区间/球算术在信号处理里**有零散应用（区间 DSP、区间滤波器），但都是"算得更稳"，
  没有变成"测量结论本身带证书"。

### 2.4 单音参数估计：LS 无偏是教科书结论

- **Rife & Boorstyn (1974)**：单音参数的 ML 估计与 Cramér–Rao 界；说明"频率已知时幅度/相位是线性 LS"。
- 这解释了第 3 节的现象：**泄漏是估计器的偏差，不是数据的性质**。这条在统计信号处理里是常识，
  但在音频测量的工程传统里被"窗"遮住了。

### 2.5 空档在哪

| 已有人做 | 本文补的 |
|---|---|
| 行业仪器到 −120 dB | 软件链到 −440 dB，并说明每一级的地板 |
| 标准假设 float64 | 把精度当自变量，给出 6.02 dB/bit 的标度律 |
| 窗用来压泄漏 | 证明"窗放进模型"后泄漏不再进地板 |
| 非相干测试靠窗 + 补偿 | 非相干测试靠精确模型 + 任意精度，**不再需要相干采样** |
| 数值误差分析（事后） | 球算术给出**事前可证明**的界 |

## 3 理论：泄漏是估计器的假象

### 3.1 经典叙事

矩形窗截一段非整数周期的正弦，DFT 的 bin 上会"漏"进邻近频率的能量，于是有了旁瓣、扇贝损失、
以及"必须相干采样或加窗"的工程规矩。这条叙事把泄漏归给**窗**。

### 3.2 正规方程视角

设数据 `x[n] = A sin(ωn + φ)`，n = 0…N−1，ω 已知，未知 (a, b)。模型 `m[n] = a cos(ωn) + b sin(ωn)`。
最小二乘解是

```
[cc cs; cs ss] [a; b] = [xc; xs],   cc = Σc², ss = Σs², cs = Σcs, xc = Σcx, xs = Σsx
```

只要 ω 正确，这个 2×2 系统就**精确**拟合数据，残差为零——**与 N 是否整数周期无关**。
非相干时 cos 与 sin 不正交（cs ≠ 0），方程组只是不那么"对角"，但仍然可解。

经典的"单 bin 投影"相当于令 cs = 0、分别解 a = xc/cc、b = xs/ss。这一步丢掉了交叉项，
于是非相干时 a、b 有偏，残差就是那条"泄漏裙边"。**泄漏是丢掉交叉项的代价，不是窗的代价。**

### 3.3 地板的解析形式

用 p 位有效精度做上述求解，残差能量来自两处：样本的表示误差（每样本 ~2⁻ᵖ）与求解的舍入。
两者的相对能量都 ~2⁻²ᵖ，于是

```
零差(dB) ≈ 6.02 · p − C(N, 估计器)
```

C 与 N、参数个数、条件数有关（本例 N=4096、2 参数，实测 C ≈ 36 dB）。
换成十进制：**每多一位十进制数字，地板抬高 20 dB**。要测 X dB，需要约 X/20 位十进制 + 余量。
440 dB → 22 位 + 6 位余量 ≈ 28 位（quad 的 34 位十进制 / 113 位二进制，绰绰有余）。

条件数：单音时 `cond = (1+|ρ|)/(1−|ρ|)`，ρ = cs/√(cc·ss)。非相干最坏 ρ 可到 0.9 量级（cond ~ 20），
对任意精度完全无压力；**多音靠得很近时条件数才会爆炸**（Δω 小 → cond ~ 1/Δω²），
但那也正是"需要更高精度"的地方，而不是"需要换窗"的地方。

### 3.4 对 IEEE 1241 的含义

标准要求相干采样，是因为它规定的估计器是**单 bin 的周期图**。如果估计器换成完整正规方程，
相干性就不再是精度的前提，只是"省事"的前提。这一点可以直接写成一句话：

> **相干采样是估计器的要求，不是被测对象的要求。**

这句话在工程上是有代价的（求解比单 bin 贵），但在"测量不必在意计算时间"的研究场景里，
代价为零。

## 4 实验

环境：Python 3.13 + mpmath 1.3（纯 Python 多精度）；fs = 8000，N = 4096，A = 0.5 满量程，
信号用 `(f·n) mod fs` 的整数相位生成。代码见 `hpm/experiments/floor_law.py`。

### 4.1 精度标度律（相干 1 kHz，完整 2×2 解）

| 工作精度 | 有效位 | 零差 | 用时（N=4096） |
|---:|---:|---:|---:|
| 20 dps | 66.4 bit | 363.4 dB | 0.38 s |
| 40 dps | 132.9 bit | 760.8 dB | 0.52 s |
| 60 dps | 199.3 bit | 1164.2 dB | 0.74 s |
| 80 dps | 265.8 bit | 1561.5 dB | 0.94 s |
| 120 dps | 398.6 bit | 2362.3 dB | 1.27 s |

线性拟合：**6.017 dB/bit**（R² ≈ 1）。120 dps 时残差能量约 10⁻²³⁶，早已低于任何物理信号。

### 4.2 非相干 + 单 bin：一条水平线

| 工作精度 | 单 bin 闭式投影 | 完整 2×2 解 |
|---:|---:|---:|
| 20 dps | 71.9 dB | 363.4 dB |
| 60 dps | **71.9 dB** | 1164.1 dB |
| 120 dps | **71.9 dB** | 2362.3 dB |

同一份数据、同一个频率假设，只差"解不解交叉项"。**精度加 100 位，单 bin 的读数一动不动。**
这就是"泄漏是估计器假象"的直接证据。

### 4.3 未知频率：三样本线性预测

正弦满足 `x[n+2] = 2cos(ω)x[n+1] − x[n]`，于是

```
ω = arccos( (x[n] + x[n+2]) / (2 x[n+1]) )
```

| 工作精度 | 频率相对误差 | 零差 |
|---:|---:|---:|
| 40 dps | 9.2e−42 | 758.0 dB |
| 120 dps | 3.5e−122 | 2361.5 dB |

与"频率已知"的情形（760.8 / 2362.3）只差 2 dB——**频率未知不是一个地板**。

### 4.4 窗放进模型：中性

非相干数据、Hann 窗、模型也乘同一个窗，2×2 解：**1164.7 dB**（无窗 1164.2 dB）。
窗既没有帮忙，也没有添乱。它只在"你不把它放进模型"的时候才有害。

### 4.5 带证书的测量

区间算术（60 dps，N=512）给出：

```
r2 ∈ [−1.88e−115, +1.88e−115]     （残差能量，严格区间，跨 0）
x2 ∈ [ 63.9706,  63.9706 ]        （信号能量）
=> 零差 ≥ 1165.3 dB               （可证明下界）
```

注意 r2 的区间**跨过 0**：这不是失败，而是最强的结论——**真实残差比这套算术的分辨率还小**。
对"测一个 DUT"来说，这正是想要的方向：我们能证明"它的误差不超过 X"，而不是"我估计它大约是多少"。

### 4.6 代价

| 项目 | 数值 | 说明 |
|---|---:|---|
| N=4096、20 dps | 0.38 s | 纯 Python/mpmath |
| N=4096、120 dps | 1.27 s | 同上；标度接近 O(N·dps) |
| C++/Arb 预期 | 快 50–200× | 球算术 + 分治 FFT；未实测 |
| 实数情形 | 2× | 上面只用了单音三参数 |

测量是离线研究，1.3 s/段完全可接受；真正贵的是"把整条链写成任意精度"的工程量，不是运行时间。

## 5 分析窗该怎么做

分三种场景，**窗的角色完全不同**：

### 场景 1 · 激励已知、DUT 是黑箱（SRC、DAC 测试）

**不要用窗。** 参考信号是解析的，直接在精确频率上解正规方程；窗只会把 DUT 的边界瞬态搅进拟合。
如果必须压边界（比如 DUT 有 20 ms 的启动瞬态），那就**把窗写进模型**：模型 = 窗 × 解析信号，
再解加权最小二乘。这样窗只改变权重，不引入偏差。

### 场景 2 · 激励已知、要出频谱图（论文/报告用）

窗仍然要，但它的职责变成**时间局部化**与**动态范围展示**，不是"压泄漏"：
- 选 DPSS/Slepian（给定带宽能量最集中），或 Kaiser（旁瓣可调）；
- 在任意精度下算窗：DPSS 是三项递推矩阵的主特征向量，mpmath 的 `eigsy` 或 Arb 都能在几百位上稳定求出；
- 画图时注明"这条谱线的裙边是窗的形状，不是信号"。

### 场景 3 · 未知信号（真实录音、现场测量）

窗 + 周期图仍然是唯一实用的路线。此时的建议是：
1. 先估一个底噪/失真目标 F；
2. 按 `bits ≥ (F + 40)/6.02` 选工作精度；
3. 窗按**分辨率**选（主瓣宽度 ~ 1/T），不按旁瓣选——因为旁瓣可以用"窗感知的最小二乘"
   （把窗放进模型、解 K 个分量的线性系统）在事后消掉；
4. 只把窗当作"时间窗"，不当作"精度工具"。

### 一句话规则

> **窗决定你看见什么，精度决定你能看多深。** 把两件事混在一起（用窗去提精度），
> 就会得到 71.9 dB 那种"加多少位都不动"的读数。

## 6 创新点

按"可发表性 / 风险"排序。每条都给出**审稿人会怎么打**与**什么能证伪它**。

### 6.1 五级地板级联（最稳）

把"测量地板"拆成五级、逐级实测、并用它预测四条不同精度的链（误差 ≤ 0 dB 到 −21 dB）。
新意在"**把测量链本身当作被测对象**"：多数论文只报告"我们测到 −300 dB"，不解释这 −300 是谁的极限。
- 审稿人会问：这是不是显而易见？—— 是，但没人把它写成可预测的模型并逐级验证。
- 证伪方式：找到一条链，读数显著高于其最低一级。

### 6.2 泄漏 = 估计器误差，相干采样非必要（最有意思）

用同一份数据证明：单 bin 投影 71.9 dB 不随精度变；完整正规方程 6.02 dB/bit 且与相干性无关。
对 IEEE 1241 的"相干采样"提出一个明确的理论替代。
- 审稿人会问：LS 无偏不是教科书吗？—— 是（Rife–Boorstyn 1974）。**新意不在 LS，而在
  "把它用于音频测量并把相干采样要求降级为工程便利"**，以及"任意精度让条件数不再重要"。
- 证伪方式：构造一个反例，使完整正规方程在非相干下仍然有偏（例如模型缺项）。

### 6.3 带证书的音频测量（最"新"，也最容易被质疑）

球算术给出严格下界，测量结论从"估计值"变成"定理"。
- 审稿人会问：证书的宽度有意义吗？—— 有：r2 跨 0 意味着"残差低于算术分辨率"，
  这是可证明的强结论；但证书宽度本身依赖实现（Arb vs mpmath），要报告实现细节。
- 证伪方式：给出一个"证书说 ≥ X 但实际 < X"的例子（理论上不可能，除非实现有 bug）。

### 6.4 次要点

- **整数相位测试信号的代数化**：激励完全由整数定义，参考值可在任意精度下精确重算，
  不引入"生成信号的浮点误差"这一项（这一步在分支 A 的论文里已经用了，但没被单独论证）。
- **四精度引擎作为被测件**：分支 A 的 binary128 版本是目前唯一能把"引擎地板"推到 440 dB 的
  被测对象，它让 6.1 的模型有了一个"每级都能量"的样本。

## 8 风险与反面意见

1. **"这不就是最小二乘吗？"** —— 对，核心是经典 LS。新意在组合与推论（相干采样非必要、
   五级模型、证书），不在算法本身。写作时必须把这一点摆在明处，否则会被当成"重新发明"。
2. **"音频界不关心 −440 dB。"** —— 确实。卖点不是"更好听"，是"可验证的 DSP 正确性"：
   编译器、FFT 库、SIMD 重排、GPU 内核的正确性都能用这条链验证。
3. **"任意精度太慢。"** —— 离线测量，1.3 s/段；C++/Arb 更快。实时场景不适用，本文也不主张。
4. **"证书依赖实现。"** —— 必须报告库版本与舍入模式；Arb 的球算术比 mpmath 的区间更严格。
5. **文献覆盖不足。** 本次检索以英文关键词为主，未系统扫 IEEE TIM / AES 会刊；
   投稿前需要一次正式的文献综述（尤其"interval/certified measurement in DSP"这一块）。
